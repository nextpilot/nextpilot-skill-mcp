## 修复 `.mdx` 指南里的 GFM 表格渲染成纯文本（**未提交**）

线上症状：`/guide/rule-schema` 的 §3.4 字段级参数等 **5 张表**全渲染成
`| 参数 | 说明 | |------|------| | topic | …` 这样一整段原文（用户截图）。

- 根因：`web/components/GuideBody.tsx` 是「一个入口、两个解析器」，按扩展名分发。
  `.md` 分支一直传 `remarkGfm`，`.mdx` 分支调 `<MDXRemote>` 时**一个 remark 插件都没传**。
  而 MDX 的默认管线只有 CommonMark —— 查锁文件坐实：`@mdx-js/mdx@3.0.1` 的 dependencies
  里只有 `remark-parse` / `remark-rehype` / `remark-mdx`，**没有 `remark-gfm`**。
  GFM 管道表格于是不是「表格」，退化成「一段带竖线的普通段落」：**不报错、不抛异常**。
- 修法：把插件收成一份 `sharedRemarkPlugins`（两条路共用 → 不会再各分叉），
  MDX 侧传 `options={{ mdxOptions: { remarkPlugins: sharedRemarkPlugins } }}`；
  并给 `mdxComponents` 补上 `table: Table`（`.md` 侧早有，`.mdx` 侧漏了 → 宽表无横向滚动外框）。

## `outputs.check = cpu_load` 的定性（用户追问，01:20）

**结论：不是笔误，是承重的历史名，绝不能"顺手统一"成 group 的 `cpu`。**

证据链（都查过）：

- `group: cpu` 是**执行槽位**（`facts.yaml` 的 `group_order`，决定 finding 的 F01/F02 顺序）；
  `check` 是**报告名**（`checksRun` / `checksSkipped`）。两者本就是两回事，多数规则恰好同名。
- `tools/calibrate/baseline/` 下 **6/6 份**冻结基线的 `checksRun` 都含 `cpu_load`。
  改成 `cpu` 会让 `compare_baseline.py` 在 6 条日志上全红。
- 26 条规则的编译产物里，**25 条 check == group，独此一条不等**；
  构建期 `build-knowledge.mjs:362` 那句 console.log 原文就写着"（显式例外）"——设计如此，非漏门禁。
- 前端只原样透传这个字符串（`web/lib/types.ts`），**没有 check 名 → 文案的映射表**。

**本轮唯一改动**：`knowledge/px4/rules/cpu-load.yaml` 的 `outputs:` 下加 6 行注释，
把上面这段"为什么"写进去。改注释不改值，`build:kb --check` 仍 OK（无漂移）。

**暴露出一个真实的门禁缝隙（未动手，留给后续决定）**：
`compare_baseline.py` 要真实 `.ulg`，在 CI 里是 SKIP 的 —— 也就是说
"把 `cpu_load` 改名"这种破坏基线的改动**云端抓不到**，只有本机 pre-push 兜得住。
可以补一条**纯静态**守卫（不需要 .ulg）：
断言 `baseline/*.json` 的 `checksRun ∪ checksSkipped.check` ⊆ 当前规则编译产物的 check 名集合。
