## MCP 与 Skill 不能合并（已核实，待老大拍板是否改造 MCP 目录）

结论：**两回事，官方规范三处直接互斥，不能合成一套。**

依据
- `web/lib/types.ts` 的 `McpServerMeta` 注释本身就写死了这个区分：
  "Skill 是模型读到的提示词与约定，MCP 服务是客户端能真正调用的工具集，
  两者的字段、评估方式和安全要求都不同。"
- MCP Registry 官方（registry.modelcontextprotocol.io）的 `server.json`：
  `name` 是**反向 DNS** `io.github.{owner}/{repo}`、大小写敏感；`description` **≤100 字符**；
  必填 `$schema` / `name` / `description` / `version` / `packages[]`（`transport.type` =
  stdio | streamable-http | sse，还带 `environmentVariables`）；可选 `repository` / `title` /
  `websiteUrl` / `remotes[]`。
- Agent Skills：`name` kebab 小写且**必须等于目录名**，`description` 1-1024（我们取严 200）。
  → **name 规则互斥**，同一个名字不可能同时满足两边。
- 语义也不同：`knowledge/mcp/` 收的是**别人的服务**（`sourceUrl` 指向 GitHub），
  Skill 是我们自己产出的提示词包。

现状（别搞混三个"MCP"）
1. `knowledge/skills/` = Skill 卡片
2. `knowledge/mcp/` = 收录的第三方 MCP 服务（只有 2 条：ardupilot-log / msfs-sim-flight）
3. CLAUDE.md §5「平台 MCP 服务」= **平台自己**将来要对外暴露的服务（阶段二，未做）
- 列表页组件是分开的：`McpGrid` / `SkillExplorer`；详情页**共用** `SkillContentTabs` /
  `SkillSidebar` / `SkillComments`（靠 `kind` 参数区分）——是 UI 复用，不是数据合并。
- 隐患：MCP 在用 `Skill*` 前缀的组件，按"命名望文生义"的口味这是个欠账，未改。

发现的实打实 bug（未修）
- 两个 MCP 条目的 frontmatter 都**没有 `changelog:`**，而
  `parseChangelogFromFrontmatter` 第 33-35 行会在没写时兜底造一条
  `{version, date: updatedAt, notes: ["首次收录"]}`。
  → `/mcp/ardupilot-log` 的"版本历史"Tab 显示 `1.4.0 / 2026-09-10 / 首次收录`，
  这条是**编造出来的**，页面上看不出真假。
- （已核实不是问题）两条的 `readOnly` 都显式写了（true / false），安全标注没漏。

## `/mcp/<slug>/server.json` 路由（老大要求）

`web/app/mcp/[slug]/server.json/route.ts`。

**先核了部署形态再动手**（这是能不能做的前提）：`docs/dev/operations/README.md` §5 写明
EdgeOne Pages 的**输出目录是 `.next`、Next.js 全栈模式、非静态导出**——所以 Route Handler
能活；`next.config.ts` 的 `outputFileTracingIncludes` 已把 `.generated/**` 带进部署包，
运行期 `fs` 读得到。静态导出的话这条路一开始就不成立。

实现要点
- 返回**文件原文**，不 JSON.parse 再 stringify：`lib/mcp.ts` 的 `McpManifest` 只声明了站点要用的
  几个字段，用 struct 再序列化一次会**静默丢掉**站点不关心的字段，manifest 就不完整了。
- slug 先过 `SLUG_RE`（`^[a-z0-9]+(?:-[a-z0-9]+)*$`）再拼路径，杜绝 `../` 穿越。
- 上游 pending 的条目没有 server.json → **404 + body 说清缺什么**，不给空对象或占位 manifest：
  客户端照占位内容去装包会装到不存在的包，而它无从判断"还没核实"还是"就是这样"。
  实测：穿越 400、未知 slug 404、`/mcp/ardupilot-log/server.json` 200 + `application/json`。
