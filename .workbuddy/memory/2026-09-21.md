## 指南页「侧栏 ↔ 正文」空白收窄

- 现象：指南页左侧导航与正文之间有一大条空白。用 Playwright 在真实 Chromium 里量（1024/1152/1280/1440/1920
  × 中英双语），根因是两处叠加：
  1. 侧栏写死 `w-48`(192px)，但导航文字中文最宽 124px、英文 151px → 侧栏**内部**白空 27~54px；
  2. 两道栏间距各 40px（`guide/layout.tsx` 的 `lg:gap-10` + `GuideArticle` 的 `gap-10`），
     加上 224px 右目录，把正文从 `max-w-3xl`(768px) 压到只剩 624px。
  - 中文下「侧栏文字右边缘 → 正文左边缘」实测 94px，英文 67px。
- 改法：侧栏 `w-48` → `w-max min-w-36 max-w-48`（宽度跟导航文字走，中文落到下限 144、英文贴合 165）；
  两道间距 40px → 32px（`lg:gap-8` / `gap-8`）。
- 改后实测：感知空白 中文 94→38px、英文 67→32px；正文（≥1280 有右目录）624→688px（中文）/667px（英文）。
- 守卫 §[19]（新增）+ 5 条变异：侧栏不许写死宽度、上下限兜底各一条、两道间距不许回到 40px。
  判据用 `<aside className="([^"]*)"` 抽出类名再按 token 判（`max-w-48` 里也含 `w-48` 子串，
  裸子串检查会误判），并且**必须先 `stripComments`**——注释里原样写着 `w-48` / `gap-10`。

## 踩到的坑

- `mutate_guards.py` 的进程被中断时（PowerShell 管道 + 后台执行那次），变异**没还原**，
  `web/components/LogFlightMap.tsx` 被留在变异状态（`errorReasons.map(` → `list.map(`）。
  已用 `git checkout --` 还原。**以后跑自证脚本要跑完看收尾，中途退出必须立刻 `git status` 查一遍。**
- 上面这个坑今天又踩了一次，而且有了新成因：**PowerShell 工具默认 120s 超时会硬杀进程**。
  每跑一条变异就要起一次 node 守卫脚本，4 条 + 基线轻松超过 120s → 进程被杀 → `finally` 里的还原
  根本没机会执行（`web/components/GuideSidebar.tsx` 的 `max-w-48` 被吃掉一次）。
  **做法：用 `--only <关键字>` 一次只跑一条，并给 PowerShell 工具显式加 `timeout: 600000`。**
  注意 `--only` 的匹配是按变异名子串，名字要能互相区分。
- `next build` 会把 `web/next-env.d.ts` 从 `.next/dev/types/*` 改写成 `.next/types/*`（该文件是 Next 自动生成的），
  提交前记得还原，避免夹带无关 diff（还原后 `tsc` 仍通过）。
- 本机两处环境限制（今天实测，别再重试）：
  - **Bash 工具的 shim 是坏的**：`dirname`/`cd` 报错，`grep`/`ls`/`rm` 全部 command not found。
    但**用绝对路径调用 node 是可行的**（`"/c/Program Files/nodejs/node.exe" ...`），后台起服务就靠这个。
  - **`agent-browser` CLI 静默失败**（装了也跑不出东西）。量页面布局直接用仓库自带的
    Playwright + Chromium（`@playwright/test`），写个 `.tmp-measure*.cjs` 脚本更快。
  - PowerShell 直接 `& python` / `& node` 拿不到回显，且中文会被按 ANSI 解码成乱码。
    解法：先 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`（Python 再加
    `$env:PYTHONIOENCODING='utf-8'`），再用 `*>&1 | Out-File -Encoding utf8` 落盘后 Read。
  - 临时脚本删不掉时是沙箱的 safe-delete（回收站）失败报 `trash-failed`，**重试一次通常就成功**。
