## 三、三件最要紧的事

### 3.1 原始日志不出浏览器

解析与规则检查全在你的浏览器里完成（Pyodide 跑 WASM 里的 Python），
原始 `.ulg` / `.bin` 一个字节都不上传。上行的只有脱敏后的结构化结论
（供 LLM 写中文说明用），不含原始轨迹。

这也是日志分析必须在浏览器里跑的原因——它是隐私承诺的实现方式。

### 3.2 结论是「算出来的」，不是「猜出来的」

数值判断全部由规则引擎做（阈值写死在 `knowledge/` 下的规则里），
LLM 只负责把结论翻译成中文，不允许改动或编造任何数值。

所以：同一个日志、同一版规则 → 同样的结论。结论不对时，问题在规则，不在模型。

### 3.3 什么格式支持到什么程度

| 格式             | 解析             | 规则覆盖                  |
| ---------------- | ---------------- | ------------------------- |
| PX4 `.ulg`       | 完整             | 26 条规则，覆盖 16 个维度 |
| ArduPilot `.bin` | 完整（自研解析） | 16 条规则，阈值仍在核实中 |

ArduPilot 侧还在跟上游对齐，规则数量与阈值可能变动——见
[`../develop/knowledge/gap.md`](../develop/knowledge/gap.md)。

## 五、这套文档怎么维护

| 角色                     | 真源                                                    | 谁改                           |
| ------------------------ | ------------------------------------------------------- | ------------------------------ |
| **用户看的正文**         | [`web/content/guide/`](../../web/content/guide)（站内） | 改完直接刷新，dev 下运行期读盘 |
| **规则清单 / schema 页** | `knowledge/` 下的规则文件（构建期生成页面）             | 改规则文件，不手改页面         |
| **本文（导航层）**       | 本文件                                                  | 入口变了、装法变了才动         |

本文只写「不落页面的事实」——入口表、装法、边界承诺。
凡是能在 `/guide` 里读到的，本文一律只给链接，不重复。
