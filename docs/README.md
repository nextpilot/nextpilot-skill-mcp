# docs/ —— 文档

一个目录，一种读者：

| 目录                            | 给谁看                                      |
| ------------------------------- | ------------------------------------------- |
| [`develop/`](develop/README.md) | **开发者 / 运维**——怎么实现、怎么跑、怎么改 |

**给用户看的内容不在 docs/**：`/guide` 站内页面的真源在 `web/content/guide/`
（入库，和 skills/mcp 一样——`web/content/` 是站点内容的唯一存储）。
判断标准就一条：**这段话用户会不会在 `/guide` 上看到**。会，进 `web/content/guide/`；不会，进 `docs/develop/`。

> **`docs/` 下的所有文档都是给人看的。** 给 AI 看的备忘是仓库根的 `CLAUDE.md`
> 与各目录下的 `CLAUDE.md`——**本目录不引用它们**，只允许反向引用。

## develop 里有什么

见 [`develop/README.md`](develop/README.md)。一句话：

| 目录            | 回答                                    |
| --------------- | --------------------------------------- |
| `quickstart/`   | 怎么跑起来、改完该跑什么检查            |
| `architecture/` | 系统怎么分层、每个板块怎么实现的        |
| `knowledge/`    | 知识库（规则/图）上游有什么、我们差在哪 |
| `operations/`   | 怎么部署、怎么排障                      |
| `roadmap/`      | 接下来做什么、已经定了什么              |
| `style.md`      | 写代码要守什么规矩                      |

## 站点内容怎么变成页面

不需要任何拷贝或同步：真源就在 `web/content/` 下、直接入库，运行期
`web/lib/content-dir.ts` 直接读盘——`web/` 是独立的 Next.js 项目，部署时只上传
它自己这一个目录，所以内容放它肚子里最稳。以前那套 `sync-content` 构建期拷贝
已随真源唯一化退役。
