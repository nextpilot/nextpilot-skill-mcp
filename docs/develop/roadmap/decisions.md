## D1. 目录布局：`web/` 不从仓库根拆平（2026-09-23 决定，维持现状）

**决定**：不把 `web/` 拆成「仓库根 + `src/`」。`web/` 保持独立 Next.js 项目。

**为什么不改**：改动面（4 份配置合并、CI、`mutate_guards.py` 29 处路径字面量、EdgeOne 控制台）
远大于当期收益；且有两项前置条件**只能在生产部署时才能看见结果**。

**重新考虑的前提**（三条都不在 Git 里，必须先实测）：

1. EdgeOne 控制台的**构建根目录**能否改指——不同步改就是"部署挂、CI 全绿"。
2. EdgeOne CLI 上传是否**严格遵循 `.gitignore`**——不遵循要补 `.edgeoneignore`。
   **这是迁移新引入的隐私风险**：迁移前构建目录是 `web/`，含 GPS 的 `.ulg` 靠"在 `web/` 之外"
   **物理隔离**；迁移后构建目录变仓库根，这道物理闸只剩 `.gitignore` 一道，此类事故不可撤回。
3. `functions/` 能否移入 `src/`——本地无法验证。

### 现状下必须记住的事（与是否迁移无关）

| #   | 事实                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 根 `package.json`（`pnpm -C web` 转发壳）与根 `pnpm-lock.yaml`（零依赖空壳）是**影子**。改依赖只在 `web/` 改，**别往根加依赖** |
| 2   | 根 `.gitignore` 含 `/pnpm-lock.yaml` 是**有意为之**（真 lockfile 在 `web/`），不要顺手删                                       |
| 3   | `public/` 只能在**项目根**——Next 源码写死 `path.join(dir,'public')`；**不存在 `src/public`**                                   |
| 4   | `web/app/` 已存在，`findDir` 优先 `./app`。**不要新建 `web/src/app`**——会被静默忽略、不报错                                    |
| 5   | `web/lib/content-dir.ts` 是运行期 `process.cwd()/content`；任何改 cwd 的调整会让内容**静默变空**（指南 0 篇），不报错          |
| 6   | `tools/testdata/logs/*.ulg` 含 GPS 轨迹，靠"在 `web/` 之外"物理隔离。**不要移进 `web/`**                                       |

## D2. 校验命名：按「怎么判定」分目录，不按 test/check 分（2026-09 决定）

**决定**：不执行 `test_* → check-*` 的大改名。目录按**被测模块**分
（`engine/` / `common/` / `dev/` / `ci/` / `setup/`），保持现状。

**诊断结论（仍然成立，供将来参考）**：`test` 与 `check` 不对应任何真实区别，
因为**三条正交的轴被压扁成一个前缀**：

| 轴                 | 取值                                             |
| ------------------ | ------------------------------------------------ |
| A 怎么判定         | 执行代码断言输出 / 扫源码找模式 / 输出给人看     |
| B 作用域           | 单元 / 契约 / 端到端 / 内容规范 / 元（机制自身） |
| C 谁跑、什么时候跑 | commit / push / 云端 / 部署后 / 手动             |

**整改思路**（若将来真做）：按轴 A 分目录、按轴 C 分阶段，两轴各自单一事实源；
轴 B 不进目录，由 `check_all.py --list` 展示（`--list` 会打印每个 job 的 `when` 条件数组）。

**命名约定**（若改名时用）：`<类型>-<模块>-<干什么>`。
类型词五个：`guard` / `check` / `test` / `probe` / `dump`。
分隔符按**调用方式**分（命令行直跑用 `-`，要被 `import` 的用 `_`——连字符 `.py` 不能 import）。

**搬家最危险的不是报错，是守卫静默失效**（扫描范围塌了一块，而它自己不会说）：

- 同批要改的路径引用**一次改完**，分批等于同一批引用改两遍。
- `pyproject.toml` 的 `testpaths` **只改一次**（引擎测试与契约测试要在**同一个提交**里搬完）。
- 变异锚点是**精确字符串**；文件搬走后 `check_all.py --mutate` 报"找不到待变异内容"是**好事**（会红），
  但要认出是路径没同步，不是守卫坏了。

### D5.4 一条"先测量后核实"的教训（防止后人重犯）

测速报告初版把「674KB 首屏资源」列为待优化项，并建议**加长缓存、开 Brotli**。
实测核实后**两条建议都不成立**：Brotli 已开（CSS 68KB → 11KB）、静态资源已是
`max-age=31536000, immutable`；674KB 是**未压缩体积**，实际传输只有 **212KB**。

> **规则**：性能结论**必须先测再写**，禁止无基线声称"有提升空间"。

另：延迟分解实测 **TLS 握手 0.30s 是唯一固定成本**（客户端 → 新加坡边缘节点，RTT 161ms），
DNS/TCP 在 1 毫秒级可忽略；连接复用后第 2 次起 TLS 成本归零。
**唯一剩余杠杆是"备案换国内节点"**。

## D7. `docs/develop/` 目录结构（2026-10 决定，同月扩为八位置）

**决定**：`docs/develop/` 按「**读者在什么时刻需要它**」分八个位置，一个主题一个落点：

| 位置            | 回答的问题                       | 读者状态             |
| --------------- | -------------------------------- | -------------------- |
| `quickstart/`   | 我怎么跑起来、写第一条东西？     | 第一天进来           |
| `architecture/` | 它是怎么设计和实现的？           | 要改代码、要懂边界   |
| `testing/`      | 什么时候跑哪些检查、怎么过门禁？ | 改完代码、等 CI      |
| `contribute/`   | 怎么求助、怎么贡献、守什么规矩？ | 动手写代码前、遇问题 |
| `knowledge/`    | 知识库（规则/图/算子）什么状况？ | 要给知识库加/改东西  |
| `operations/`   | 怎么部署、怎么排障？             | 上线、线上出问题     |
| `roadmap/`      | 接下来做什么、已经定了什么？     | 接手待办、查决策     |

**演进**：最初为六分类（`style.md` 单文件放 `develop/` 根、`checks-by-stage.md` 归
`quickstart/`）。落地后两份文件各自超过 300 行，按「一份 md 只讲一个主题」拆成子目录：
`style.md` → `contribute/`（三份：README / code-style / docs-and-assets），
`checks-by-stage.md` → `testing/`（六份：README / checks-by-stage / check-catalog /
guards / log-regression / pitfalls）。拆分依据见铁律 2。

**为什么规范进 `contribute/` 而不是独立 `requirements/` 目录**：代码风格与「如何贡献、
如何获取帮助」是同一读者在同一个动作（动手写代码）前后需要的东西，放一起少一跳；
`requirements/` 目录名与仓库里真正的依赖清单（package.json / requirements 惯例）撞车，裁掉。

**为什么 `checks-by-stage` 归 `testing/` 而不是 `quickstart/`**：`quickstart/` 只回答
「怎么上手」（装环境、跑起来、写第一条东西）；「什么时候跑哪些检查」是**日常开发循环**
的一部分，与速查、清单、守卫、坑同属质量门禁主题，单独立目录才讲得开。

**为什么 `architecture/` 按系统分层拆七份**：一个板块一份，避免"一份文档讲三件事"。
当前为 `README`（四层总览）+ `engine` + `provider` + `web-app` + `mcp-server` +
`error-reporting` + `admin-site-settings`。

**四条铁律（同时确立）**：

1. **一个 md 只讲一个主题**，不许两份文档说同一件事。
2. **一份 md 超过约 300 行就该问要不要拆**——按主题拆子目录，拆出的目录配短 README。
3. **`docs/` 下任何文档不得引用 `CLAUDE.md`**；只允许反向（`CLAUDE.md` → `docs/`）。
4. **`CLAUDE.md` 是给 AI 看的，`docs/` 下其余都是给人看的**——不是 AI 备忘录。

**过程文件的处置**：本轮的规划文件（`docs-system-plan.md`）在落地后按 D4 即删；
结论全部收进本条 D7，不另留文档。
