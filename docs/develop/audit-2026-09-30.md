## 二、SEO：骨架齐全，3 处实缺陷（优先级最高）

### 已完成得不错的部分

- `sitemap.ts` / `robots.ts` / `manifest.ts` / `opengraph-image.tsx` / `feed.xml` 全有
- `lib/seo.ts` 提供 `makePageMeta` 单一入口，canonical + hreflang + OG + Twitter Card 一次生成
- JSON-LD 覆盖 Organization / WebSite / TechArticle / SoftwareApplication / BreadcrumbList / FAQPage
- 详情页 canonical 与 hreflang 实测正确输出：

  ```html
  <link rel="canonical" href="https://skill.nextpilot.org/en/skills/pid-autotune-assistant" />
  <link rel="alternate" hreflang="zh-CN" href=".../zh/skills/..." />
  <link rel="alternate" hreflang="en" href=".../en/skills/..." />
  ```

### 缺陷 1：英文页面的 `og:url` 丢 locale 前缀

`lib/seo.ts:79` 这一行：

```ts
const ogUrl = path ? `${SITE_URL}${path}` : SITE_URL; // 注意：没带 locale
```

实测英文页产物：

| 标签        | 实际值                                          | 应该是                                 |
| ----------- | ----------------------------------------------- | -------------------------------------- |
| `canonical` | `.../en/skills/pid-autotune-assistant` ✅       | 同左                                   |
| `og:url`    | `.../skills/pid-autotune-assistant` ❌ 缺 `/en` | `.../en/skills/pid-autotune-assistant` |

**抽查 50 个页面，44 个的 `og:url` 缺 locale。** 后果：社交平台分享英文页时，抓取的是中文版 URL，卡片内容可能串语言。

修法：`ogUrl` 复用 `canonicalUrl` 即可（一行改动）。

### 缺陷 2：英文页面的 `<html lang>` 硬编码为 `zh-CN`

`app/layout.tsx:105` 写死 `<html lang="zh-CN">`，而 `[locale]/layout.tsx` 没有覆盖它。实测：

- `/en/skills/...` → `<html lang="zh-CN">` ❌（`og:locale` 却是 `en_US`，自相矛盾）
- `/zh/skills/...` → `<html lang="zh-CN">` ✅

**这是明确的 SEO 扣分项**：搜索引擎据 `lang` 判断页面语言，英文页标成中文会影响英文收录与语音搜索。当前靠客户端 JS（`LanguageProvider`）事后改 `document.documentElement.lang`，但爬虫首屏拿到的仍是 `zh-CN`。

修法：`[locale]/layout.tsx` 里把 `lang` 作为属性下发（Next.js 15+ 支持在嵌套 layout 返回 `<html>`，或改用 `params.locale` 驱动根 layout）。

### 缺陷 3：sitemap 的 `lastModified` 是假值

`lastModified: new Date()` 在每个请求时求值 → 整份 sitemap 的"最后修改时间"永远是"现在"。搜索引擎会据此判断内容一直在变，反而降低对 lastmod 的信任度（Google 明确说会忽略不可信的 lastmod）。

修法：静态页用构建期时间或干脆省略；详情页已经有正确的 `skill.updatedAt` / `doc.updatedAt`，把静态页也接上即可。

### 其他 SEO 待办（优先级次之）

- **无 `noindex` 兜底**：`/me`、`/admin/settings` 只靠 `robots.ts` 的 disallow，未加 `<meta name="robots" content="noindex">`。robots.txt 只是"建议"，页面级 noindex 才是硬约束。
- **`productJsonLd()` 定义了但从没调用**（`lib/seo.ts:246`），是死代码。
- **`speakableJsonLd()` 实现有问题**：`xpath` 全部映射成 `/html/head/title`，忽略了传入的参数，等于没做 speakable。要么修实现，要么删掉。
- **feed.xml 未在 robots/sitemap 里互相引用**，RSS 发现性偏弱。
- **缺 `en` 站点地图分语言标注**（`xhtml:link` 目前靠 `alternates` 生成，是对的，但 `guide` 详情页实测未产出 HTML 产物，需确认是否被静态化）。

## 三、性能：无预算、无监控

### 实测数据

| 页面   | 首屏 JS 合计 | 备注                                   |
| ------ | ------------ | -------------------------------------- |
| 首页   | **642 KB**   | 含一个 228 KB 的 polyfill chunk        |
| `/log` | **727 KB**   | 分析页，Plotly / Leaflet 已动态 import |

Plotly（228KB 那个大 chunk 为 polyfill，Plotly 本身走动态 import）与 Leaflet 已用 `await import()` 懒加载，这点做对了。但：

- **没有任何体积预算**（`package.json` 无 `bundle` / `analyze` 脚本，`next.config.ts` 无 `@next/bundle-analyzer`）。目前**无法知道**哪次改动让首页胖了 50KB。
- **无 Core Web Vitals 上报**。虽然有百度统计，但拿不到 LCP / INP / CLS。
- **首页 642KB JS 偏胖**。一个以内容为主的首页不该有这个量级；polyfill chunk 值得查是不是 `browserslist` 目标过宽。

建议：

1. 接 `@next/bundle-analyzer`，给首页/`/log` 设体积预算（如首页 < 400KB），进 CI。
2. 首页改成 RSC 优先，把非交互组件从 client bundle 移出去。
3. 接 Web Vitals API → 上报到现有 `/api/issues` 同款链路，或接 EdgeOne 自带分析。

## 六、安全：基础扎实，缺响应头

### 做对了的

- `check_secrets` 门禁：479 个受控文件零凭据。
- **错误上报链路设计严谨**：浏览器不碰 issue token（token 只在边缘函数），IP 日限流 20 次，body 上限 64KB，栈脱敏后截 4KB，`waitUntil` 异步建单不阻塞用户。
- `robots.ts` 已 disallow `/api/`、`/internal/`、`/edge-dev/`。

### 缺的：**零安全响应头**

全仓库搜不到 `Content-Security-Policy`、`X-Frame-Options`、`Strict-Transport-Security`、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`——`next.config.ts` 的 `headers()` 只配了 `Cache-Control`。

这意味着：

- 无 CSP → 一旦有 XSS 注入点（项目里有 `dangerouslySetInnerHTML` 用于百度统计），无第二道防线。
- 无 `X-Frame-Options` → 可被任意站点 iframe 嵌套（点击劫持）。
- 无 HSTS → 首次访问可被降级到 HTTP。

修法：在 `next.config.ts` 的 `headers()` 加一组全局头。CSP 建议先上 `Content-Security-Policy-Report-Only`，观察一周再转正。

2. 加 `@axe-core/playwright`，在现有 e2e 里对 5 条已覆盖路由加 a11y 断言。
3. 加 skip-link（一个 `<a href="#main">`，成本极低）。
